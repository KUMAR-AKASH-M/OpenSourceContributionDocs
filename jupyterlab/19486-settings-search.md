# #19486 — "Find" is disabled in the Advanced Settings JSON editor

**Status:** Open — extended to System Defaults, [PR #20414](https://github.com/jupyterlab/jupyterlab/pull/20414), head `4b306fcfd1`, 12 commits. PR body updated and the new video posted as a comment; the branch push to the fork was still pending when this was written. No review yet; CI is gated, with 11 workflows awaiting maintainer approval.

## The issue

The Find command was disabled in the Advanced Settings JSON editor. Ctrl+F already worked through CodeMirror's native search, so the gap was only the menu and `documentsearch` command — the editor existed, but the application refused to search it.

## What was done

The design adds a `SettingEditorSearchProvider` that claims the `MainAreaWidget<JsonSettingEditor>` and reuses the public getter `JsonSettingEditor.source`, so no new public API was needed. It searches only the editable user settings editor, not the read-only defaults pane, and that limit is disclosed in the PR. The repo Jest suite came back 30/30 across five suites. During review, krassowski pointed out that the search bar should not cover the settings editor; the cause was the setting editor's own `base.css`, which stretched every direct `.lm-Widget` child to fill the panel. The fix went into this PR as a `:not(.jp-DocumentSearch-overlay)` guard plus a new Jest test, at his request. Merge conflicts were resolved along the way, with the merge commit `c6fb16f2dd` on main `1c917ab15`. A video of the fix was recorded and attached.

## The System Defaults extension (2026-11-17 – 2026-11-19)

krassowski commented on 2026-11-17 that the search only covers User Preferences, not System Defaults, and Ctrl+F does not bring it up there — "more work is needed". Kumar replied on the PR the next day that he would extend it to System Defaults, with Replace staying disabled in that pane since it is read-only, and the fix was built in the same PR rather than argued about.

The extension searches whichever pane has focus. The provider tracks the focused pane with `focusin` listeners on both editor hosts and reads `hasFocus()` live, keeps one `CodeMirrorSearchHighlighter` per pane (clearing the previous pane's highlights on switch), marks defaults matches read-only, and refuses Replace there. Two read-only accessors support it: `RawEditor.defaults` and `JsonSettingEditor.defaults`. The work landed as four commits on the laptop branch: a test commit (7 new Jest tests, including pane switching, initial query from a defaults selection, and Replace refusing defaults), the fix commit, a lint-fix commit, and a one-line type-narrowing fix. A merge of `upstream/main` (`8f3ff648c9`, commit `dcc5ed9475`) resolved conflicts in the three manifest files, keeping both main's `^4.7.0-beta.2` bumps and the branch's four added dependencies.

Verification on the laptop: `jlpm build:test` clean, Jest 21/21 across `searchprovider.spec.ts` and `searchOverlay.spec.ts`. The PR body was updated (two sentences, nothing else) and a new recording posted as a comment.

## What we learned

- Repo-generated files are tracked and must be committed when dependencies change: `style/index.css`, `style/index.js`, `tsconfig.json`, `tsconfig.test.json`, and `yarn.lock` are all regenerated by `jlpm integrity` or install, and leaving them out breaks the build.
- Repo Jest loads the compiled `lib/`, not `src/`. Run `jlpm build:test` before running Jest, or you are testing yesterday's code.
- GitHub renders a video as an inline player only when its bare URL sits alone in its own paragraph, and comment attachments reject videos over 10 MB — compress recordings before attaching them.
- When a reviewer asks for a fix in the same PR, do it in the same PR. The overlay fix belonged here, not in a follow-up.
- ESLint typecheck passing is not the same as the build passing. The `cmHandler` getter returned a field typed `CodeMirrorSearchHighlighter | null`, and TypeScript could not narrow it to non-null — a `TS2322` the eslint typecheck never reported, because it runs lint rules with type information, not full compilation. Only `jlpm build:test` (`tsc`) catches that. Treat the build as the type gate, not the lint.
- A failed build leaves stale `lib/` behind, and the next typecheck then reports phantom errors against the old declarations — 14 of them here, including tests failing on a `defaults` property the new code had already added. Fix the root error and rebuild before chasing the rest.
- Keep the handover prompt in sync with the copy on the laptop. The laptop agent stopped mid-handover because its `LAPTOP-PROMPT.md` was the old version, where Step 3 was still the video rather than the merge. Every new patch goes with an updated prompt file, attached, not just named by path.
- Watch the video frames yourself before calling it verified. The first recording of the defaults search had a caption claiming a Replace that never happened — the search box still held the previous query, so the new text was typed into it, no match was found, and the editor was unchanged. The re-record cleared the search box first, and the frames were checked before the video went on the PR.
- Beware angle-bracket text in fetched API output. `<JsonSettingEditor>` can be swallowed when a JSON body is rendered, making `MainAreaWidget<JsonSettingEditor>` look like `MainAreaWidget` — check the raw text before "correcting" a phrase that was right all along.
