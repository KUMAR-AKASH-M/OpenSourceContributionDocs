# #19486 — "Find" is disabled in the Advanced Settings JSON editor

**Status:** Open, ready for review — [PR #20414](https://github.com/jupyterlab/jupyterlab/pull/20414), head `c6fb16f2dd`, 7 commits. No review yet; CI is gated, with 11 workflows awaiting maintainer approval.

## The issue

The Find command was disabled in the Advanced Settings JSON editor. Ctrl+F already worked through CodeMirror's native search, so the gap was only the menu and `documentsearch` command — the editor existed, but the application refused to search it.

## What was done

The design adds a `SettingEditorSearchProvider` that claims the `MainAreaWidget<JsonSettingEditor>` and reuses the public getter `JsonSettingEditor.source`, so no new public API was needed. It searches only the editable user settings editor, not the read-only defaults pane, and that limit is disclosed in the PR. The repo Jest suite came back 30/30 across five suites. During review, krassowski pointed out that the search bar should not cover the settings editor; the cause was the setting editor's own `base.css`, which stretched every direct `.lm-Widget` child to fill the panel. The fix went into this PR as a `:not(.jp-DocumentSearch-overlay)` guard plus a new Jest test, at his request. Merge conflicts were resolved along the way, with the merge commit `c6fb16f2dd` on main `1c917ab15`. A video of the fix was recorded and attached.

## What we learned

- Repo-generated files are tracked and must be committed when dependencies change: `style/index.css`, `style/index.js`, `tsconfig.json`, `tsconfig.test.json`, and `yarn.lock` are all regenerated by `jlpm integrity` or install, and leaving them out breaks the build.
- Repo Jest loads the compiled `lib/`, not `src/`. Run `jlpm build:test` before running Jest, or you are testing yesterday's code.
- GitHub renders a video as an inline player only when its bare URL sits alone in its own paragraph, and comment attachments reject videos over 10 MB — compress recordings before attaching them.
- When a reviewer asks for a fix in the same PR, do it in the same PR. The overlay fix belonged here, not in a follow-up.
